## Final product decisions

1. Preserve target-vs-actual capture separation: `r1-r2-r3.contract.snap` is immutable target input; `output/ratatui-captures/*` are refreshable review artifacts from live Rust output.
2. Keep the design-reference identity header in the live product path: `OPPi`, provider/model, permission mode, status, and responsive thread/goal context.
3. Keep the planned live OPPi footer chips, but add each chip group only if it fully fits the current terminal width.
4. Treat CSS-only browser effects as intentionally impossible in static Ratatui snapshots.
5. Keep `/model` as the main OPPi model selector; expose per-role/per-task model routing from `/settings` instead of the primary model picker.
6. Make `/settings` the explicit exception to the design mock: it should match Pi `/settings:oppi` with section tabs and Pi-style rows.

## Verdict

Plan 62 is closed for target-UI parity as defined by the current plan: exact R1/R2/R3 gates pass, frame 03-10 Rust goldens pass, live/product captures now exercise the actual renderer, `/settings` follows the requested Pi-style exception, and browser-only effects are classified as intentionally impossible rather than open parity bugs.
