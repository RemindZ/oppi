Source of truth for the original Pi-based OPPi settings UI: `packages/pi-package/extensions/memory.ts` (`OppiSettingsComponent`).

Audit date: 2026-05-05.

Related sanity pass: `docs/native-ui-pi-parity-sanity.md` covers model selector sourcing/sorting, input/slash parity, and remaining native-vs-Pi UI gaps.

## Product decisions from this pass

1. Keep native-only model/provider controls in the Pi settings section; they are useful and clearer than the old Pi model behavior.
2. Use the original Pi settings presentation style for native settings: emoji section tabs, vertical tab rail in Ratatui, left/right tab movement in the retained TUI, and two-line rows with `label — value` plus a dim description.
3. Do not fake unsupported toggles. Missing settings should be implemented with real backing state/commands before being shown as editable controls.
4. Main model selection must not be polluted by role/per-task model overrides; role models belong in settings/role flows.
